# ADR Agent Guidance

## Purpose

This directory stores Architecture Decision Records (ADRs) for Ospro.

## Naming

- File pattern: `NNNN-short-kebab-case-title.md`
- Example: `0002-introduce-hardware-abstraction-layer.md`

## Required Sections

- Status
- Date
- Context
- Decision
- Consequences

## Rules

- Keep ADRs concrete, short, and falsifiable.
- Record meaningful alternatives when relevant.
- Do not rewrite prior ADR history; supersede with a new ADR.
- If an ADR changes implementation direction, update `AGENTS.md` and `OSPRO.md` in the same change set when applicable.
