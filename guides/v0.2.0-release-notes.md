# Ospro v0.2.0 Release Notes (Draft)

Release date: TBD  
Branch: `v0.2.0-rust`

## Summary

`v0.2.0` migrates runtime behavior from Python `v0.1.0` to Rust with parity-focused fixtures, deterministic control/state handling, and touch UI integration.

## Highlights

- Typed runtime config with legacy Python schema compatibility.
- HAL traits with mock backend and Raspberry Pi backend skeleton.
- Sensor/actuator ports and conversion parity tests.
- Control state machine with deterministic transitions and fault handling.
- Slint touch UI with live metrics and extraction review panel.
- Static telemetry chart rendering and diagnostics CSV generation.
- WS7.1 parity hardening fixes (artifact parity, runtime supervision, actuator cleanup, profile loading, review UX).

## Known Constraints

- Raspberry Pi HAL implementation remains a skeleton for GPIO/PWM/SPI/I2C (unsupported errors until implemented).
- On-device sign-off required before release finalization.

## Upgrade Notes

1. Install Rust stable toolchain on deployment host.
2. Keep `config/config.json` and `config/profiles/*.json` aligned with expected runtime values.
3. Use `OSPRO_CONFIG_PATH` only when intentional; fallback behavior is enabled.

## Rollback Checklist

1. Stop Rust runtime process.
2. Restore previous known-good deployment branch/tag.
3. Restore prior config and diagnostics retention policy.
4. Run smoke checks:
   - runtime start
   - extraction start/stop/reset
   - artifact generation
5. Record rollback cause and incident details in project log/issue tracker.
